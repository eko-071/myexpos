# Running a user program

## XSM Unprivileged Mode Execution

- In privileged mode, a memory address refers to the actual memory address.
- However, when in unprivileged mode, a memory address will be treated as a logical address and convert it to its corresponding physical address using the **address translation mechanism** of XSM.

### Paging Specification

- Every user mode program has an associated page table which maps its virtual address space to the machine's physical address space.
- Base address of the page table is stored in the **Page Table Base Register** (PTBR).
- Number of entries in this page table is stored in the **Page Table Length Register** (PTLR).
- These must be set up in privileged mode.
- An entry contains 2 words: one for the **physical page number** in memory where logical page is loaded, and one for a **4-bit sequence of flag bits** storing auxiliary info.
- This 4-bit sequence is stored as follows:-
    - **Reference Bit**: 0 initially, and set to 1 by machine hardware when the page is accessed for the first time.
    - **Valid Bit**: 0 if entry is invalid, 1 if the first word of this entry corresponds to a valid physical page number. Normally set by application, typically the OS.
    - **Write Permission Bit**: 1 if user mode program is allowed to write into the page, 0 otherwise.
    - **Dirty Bit**: 0 initially, set to 1 by machine if an instruction modifies the contents of the page.

### Address Translation

- The addresses generated by the machine while executing in user mode are logical addresses.
- The paging hardware translates them to physical addresses using the page table.
- We first calculate the logical page number and offset:
    - Logical page number = Logical Address DIV 512
    - Offset = Logical Page Address MOD 512
- Location of the page table entry = PTBR + 2 * Logical page number
- The value stored in the first word here is the physical page number.
- Physical address = Physical page number * 512 + offset

### Why Unprivileged?

- OS will have to allow concurrent execution pf other user programs.
- We should be careful to not allow a user program to run malicious code that could corrupt anything else.
- This requires us to create unprivileged mode, where there is a limited set of instructions, and limited memory space and system resources.
- When a program is run in unprivileged mode, only a restricted machine model is available to the program.
- Paging allows the OS to give each user program a virtual address space.

### Setting up Paging

- The OS must set up the applications's page table data and values of PTLR and PTBR, which must run in privileged mode.

1. Set the PTLR register to define the limit of address space.
> If an instruction refers to a logical address beyond this limit, the machine will raise an exception, which results in the machine switching to privileged mode and control transferred to the exception handler (1024).
2. Set up a valid page table in memory, and the PTBR register to the beginning address of the page table.
3. Set up the application's stack, and set SP to point to the top of the stack.
4. Compute the physical address corresponding to the logical address in SP. Then store logical address of the first instruction that must be fetched after IRET here, and execute IRET.
> IRET instruction changes the mode to unprivileged, then transfers the contents of logical address in stack into IP and decrement the stack pointer.

> It can return to privileged mode using the trap instruction INT n, where n can be from 4 up to 18. It increments SP and transfers contents of IP to stack, switches to privileged, and IP is loaded with a value that depends on n.

## XEXE executable header

- 8-word header, after which the code is present.
- First word is set to 0.
- The second word is the entry point, the logical address of the first instruction to be executed.
- The remaining 6 words can be ignored for now.
- eXpOS ABI stipulates that an XEXE executable must fit into 4 pages of memory => a file can have a 8-word header with maximum 1020 instructions.

## Software Interrupts

- INT 4 to INT 18 are called software interrupts or traps.
- The XSM machine has an **interrupt vector table** that maps each interrupt number to a corresponding address.
- Stored starting from physical address 492 of memory.
- 492, 493, 494, 495 stores the addresses of the exception, timer, disk, and console interrupt handlers.
- 496 contains the address of the first trap handler INT 4, 497 INT 5, and so on.
- Reason for traps: a regulated access mechanism through which an application can invoke an OS routine to do tasks like input-output or disk access which are not permitted in unprivileged mode.
- OS handlers that are called from user programs for privileged tasks are known as system call routines.
